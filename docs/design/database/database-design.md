# HDFS 网盘基础版数据库设计

本文是设计草案，不代表功能已经实现。配套 `schema.sql` 用于 MySQL 8.0.17+ / 8.4 的独立空数据库，不包含数据库或账号创建、生产凭据、删表语句。文件内容存放于 HDFS，MySQL 保存账号、文件元数据和任务状态。单节点 HDFS 和数据库都需要独立备份。

## 数据对象

| 表 | 用途 | 关键约束 |
| --- | --- | --- |
| `nd_user` | 登录账号、密码哈希及状态 | 登录名唯一；密码只保存经过适当加盐的慢哈希，例如 Argon2id 或 bcrypt |
| `nd_node` | 文件与文件夹共用的目录树 | `(user_id, parent_id, name)` 唯一；`version` 用于并发版本检查 |
| `nd_upload` | 上传请求、目标与恢复状态 | `(user_id, request_id)` 唯一；临时与正式对象标识各自唯一 |
| `nd_storage_gc` | 待清理 HDFS 对象的任务 | 对象标识唯一；可重试、对账和恢复 |

`nd_user` 与 `nd_node`、`nd_upload`、`nd_storage_gc` 分别是一对多；上传任务可关联一个发布中的文件节点。`nd_node` 的非零 `parent_id` 指向同一用户的文件夹节点，`0` 表示该用户的虚拟根目录。0 是非空值，因此根目录也受到名称唯一约束。

虚拟根目录不是数据库行，不能使用普通父节点外键。每次写入时，服务端必须验证非零父节点存在、属于当前用户、类型为 `FOLDER` 且状态为 `READY`；对虚拟根目录锁定该用户行，对普通父目录锁定父节点行。移动还须检查来源、目标和祖先链，禁止移动到自身或子目录。涉及多节点时统一排序加锁，处理数据库死锁并有限重试。对文件夹删除与子节点写入采取相同锁约定，并在持锁后重新检查。基础版建议仅允许删除空文件夹，非空时提示先清空。

## 命名和冲突

文件与文件夹共用名称空间。`nd_node` 的名称使用 `utf8mb4_0900_bin`，区分大小写、按 Unicode 码点比较，并区分末尾空格；服务端在校验和持久化之前应统一 Unicode NFC，并限制 1–191 个字符，拒绝 `/`、NUL、控制字符、`.`、`..` 及其他不受支持的名称。索引只保证数据库里实际存储值的唯一性，规范化和合法性检查由服务端负责。[MySQL 排序规则文档](https://dev.mysql.com/doc/refman/8.0/en/charset-mysql.html)

上传同名时提示“保留两份”或“跳过”，不静默覆盖；创建目录、重命名、移动遇到同名时提示并取消。保留两份的候选名由服务端生成并写入；遇到唯一键竞争时重新生成并有限重试，而不是先查再无条件写入。`PENDING` 和 `DELETING` 节点也占用名称，直到对应任务结束或被恢复清理，避免处理中复用名称。

读取后修改、移动或删除时须携带客户端看到的 `version`，服务端在同一事务中验证并更新版本。版本不匹配或资源已删除时返回冲突并提示刷新；所有权由认证用户决定，不信任客户端提供的 `user_id` 或 HDFS 路径。

## 上传与跨系统恢复

1. 使用认证用户、请求幂等键、目标目录和上传参数创建 `nd_upload`。重试携带相同键时返回原任务；如请求参数（目录、名称、长度及已提供的摘要）不一致，拒绝该请求。`request_id` 必须由客户端或服务端稳定生成，不能每次重试改变。
2. 服务端生成不可猜测、不可复用的 ASCII `temp_key` 和 `final_key`，记录后将数据写入临时对象。不要使用用户输入的文件名拼接真实 HDFS 路径。校验大小、必要时校验 SHA-256；中断后第一版重传完整文件。
3. 发布前以事务锁定并验证目标目录，创建 `PENDING` 文件节点预留名称，记录 `node_id`、目标名称及 `FINALIZING` 状态。冲突时进入 `CONFLICT`，由用户选择跳过或保留两份；冲突选择必须幂等且再次验证目录。
4. 在 HDFS 中将已关闭并校验的临时对象发布到唯一正式对象标识；再用数据库事务将节点设置为 `READY`、任务设置为 `COMPLETED`。正常列表和下载只展示 `READY` 文件；验证完成前不返回成功。
5. HDFS 与 MySQL 之间没有共同事务。服务崩溃时必须按任务状态和实际对象重新核验，幂等地完成或回滚；定期对账、延迟处理超时临时对象，并记录 `nd_storage_gc` 重试。不能仅凭过期时间删除正在使用的对象：应持锁/认领任务、检查状态及引用，设置安全宽限期，并恢复长时间处于 `PROCESSING` 的清理任务。HDFS 中无记录对象也要根据受控前缀和宽限期对账。

删除文件时先校验版本和权限，在数据库事务中标记删除并记录清理任务；之后异步删除 HDFS 对象、更新数据库状态。下载中的文件与清理任务需协调，防止清理仍被引用或正在读取的对象。清理失败应重试并报警。失败恢复策略需要实现与故障注入测试，表结构本身不提供跨系统原子性。

## 最小验证

- 同用户同目录文件与文件夹同名插入被唯一约束拒绝，含虚拟根目录；不同用户或不同目录允许同名。
- 同时上传同名文件时，最多一个请求取得指定名称；保留两份并发生成的候选名称仍保持唯一。
- 同用户重复幂等键只产生一个上传任务；不同参数使用同一键被应用拒绝。
- 多窗口对旧版本进行移动、重命名或删除时，过期请求不覆盖新状态。
- 上传中断、数据库事务失败、HDFS 写入或发布失败及服务重启后，文件不会误显示成功；恢复任务不删除活动对象。
- 无权访问其他用户的数据；验证目录删除与并发写入、存储空间不足及失败重试。

目前不包含分享、回收站、在线预览、历史版本、断点续传或配额；这些能力加入时需扩展数据模型和测试。
