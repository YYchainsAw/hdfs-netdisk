# 分片上传与下载实现说明

本功能目前只支持同一台服务器上的单个 server profile 后端进程。
`/run/lock/netdisk-multipart.lock` 用于阻止该主机上两个 server 进程同时运行；不得用其他配置或其他主机同时访问同一数据库和 HDFS 上传目录。跨主机部署需要重新设计分布式租约、清理和隔离，不能依赖本机锁。

客户端先以 8 MiB 分片计算全部 SHA-256，再使用唯一 requestId 创建任务；服务端一次性保存摘要清单。同 requestId 复用必须携带完全一致的信息和摘要。重选文件时需逐片比对完整摘要清单。分片按 index 并发上传，服务端校验长度和 SHA-256，每次写入使用唯一对象标识并用租约限制旧写入者提交。终结时先在数据库锁定目标目录并占用文件名称，再流式合并到唯一 HDFS 对象，完成后将节点标记 READY。进度中的分片已传完不代表最终发布已成功；中断或响应超时时，应查询任务状态并通过幂等重试恢复。

上传结束时冲突策略为 FAIL、KEEP_BOTH 或 SKIP，禁止静默覆盖。取消接口返回 SKIPPED，文件已完成时不能通过上传取消接口删除。文件名、用户归属和同名约束均由后端校验。请求的文件路径不得直接用于 HDFS 路径。

默认上限为单文件 2 GiB、每用户最多 2 个活跃任务且最多 2 GiB、全局最多 4 个活跃任务且最多 4 GiB，最多 4 个分片写入和 1 个合并。任务有效期 7 天；终态至少保留 30 天，便于查询与幂等处理。创建任务时根据活动任务全部大小的两倍及至少 10 GiB 余量检查 HDFS；写分片和合并前再次检查。HDFS 与其他服务共享磁盘，外部服务可以在检查后继续占用空间，因此这些检查不能提供绝对磁盘空间保障。

后台清理仅处理服务器生成的对象 key，并在同一进程内等待全部活动写入结束，检查数据库引用后延迟删除；失败后重试，空任务目录使用非递归删除。服务重启时获取本机排他进程锁，再释放上一次进程遗留的租约。不可在绕过锁的进程或不同宿主机上并发运行，且不能将 HDFS 服务暴露到公网。

首次启用需要先对目标数据库执行单独的 `multipart-schema.sql`。不要把数据库密码写入仓库。部署前应在隔离 MySQL 和隔离 HDFS 路径上测试分片重传、同名并发、断线、重启、跨用户读取、取消、垃圾回收、磁盘不足及下载内容一致性；确保备份和回滚方案可用。该设计不是高可用方案，单节点 HDFS 也不等同于数据备份。
