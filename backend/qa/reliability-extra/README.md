# 上传可靠性隔离回归

该回归使用一次性 MySQL 8.4 容器和真实 HDFS 随机测试目录，验证已有上传实现，不连接生产数据库，也不读取或删除生产用户文件。它以约 1 MiB 文件运行，不执行 2 GiB 压测。

覆盖：

- 同一幂等键同时创建上传任务时只产生一条记录；相同请求可重试，变更摘要时返回冲突。
- 同一分片并发写入和重试后只保留一份有效记录；完成后重复提交不会重复生成文件，下载内容与原文一致。
- 目录存在活动上传时不能删除，取消后可以删除；取消任务不能继续写入。
- 过期任务进入终态后，其临时文件先保留至回收时间，再能被安全删除；已完成的用户文件不受影响。

运行条件：Linux、Docker、本地 `mysql:8.4` 镜像、Java 17、Python 3、`openssl`、`sudo` 和已启动的 HDFS；服务器可用内存至少约 1.4 GiB，Maven 依赖已缓存。脚本默认使用 `/www/wwwroot/netdisk` 的源码和数据库脚本，亦可通过 `NETDISK_QA_PROJECT_ROOT`、`NETDISK_QA_BACKEND_SRC`、`NETDISK_QA_SCHEMA` 指定测试副本。覆盖路径时，数据库仍由脚本新建，不要传入生产数据库凭据。

```bash
bash run-reliability-extra.sh
```

脚本生成随机容器名、MySQL 密码和 HDFS 测试目录；服务端锁仅在本次复制的测试源码中更换为独立路径。启动前会检查锁路径替换是否成功。退出时只清理本次容器、临时目录、锁文件及本次随机 HDFS 目录；若进程被强制终止，需要按本次标识核对后再手动清理。

此测试不代替断电、网络分区、2 GiB 大文件或长期压力测试。模拟磁盘不足及进程强杀恢复见相邻的 `integration-qa` 测试说明；真实服务的数据仍需单独备份。
